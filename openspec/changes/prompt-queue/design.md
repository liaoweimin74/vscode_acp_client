## Context

当前 vscode-acp 的 PromptInput 组件已有一个简单的排队机制：当 `isStreaming=true` 时，用户发送的消息会被追加到 `queuedPrompts` 数组，显示为带 X 删除按钮的小标签。`stream_end` 事件触发时自动发送队列中的第一条消息。ESC 取消当前会话时，若有排队消息也会自动发送第一条。

用户需要更直观的排队交互：排队提示词显示在输入框上方，右侧有向上箭头按钮可中断当前会话并立即发送。

## Goals / Non-Goals

**Goals:**
- 排队提示词显示在输入框上方，视觉上与输入框关联
- 每个排队提示词右侧显示向上箭头按钮，点击可中断当前会话并立即发送该提示词
- 当前会话完成后，排队提示词自动发送
- 发送后从队列中移除

**Non-Goals:**
- 不支持多个排队提示词的重新排序
- 不支持排队提示词的编辑
- 不改变 ACP 协议层的取消机制

## Decisions

### 1. 向上箭头按钮行为：取消 + 发送

**决策**: 点击向上箭头时，先调用 `cancelPrompt()` 取消当前会话，然后立即发送该排队提示词。

**理由**: 这与现有 ESC 取消后自动发送第一条排队消息的行为一致。用户点击箭头的意图是"我要这个消息现在就发出去"，必须先停止当前流式响应。

**替代方案**: 仅发送排队消息而不取消当前会话 — 不可行，ACP 协议同一 session 同时只能有一个活跃的 prompt。

### 2. 保留 X 删除按钮

**决策**: 同时保留 X 删除按钮和向上箭头按钮。X 在左侧，箭头在右侧。

**理由**: 用户可能想从队列中移除一条消息（打错了），也可能想立即发送。两个操作都需要。

### 3. 自动发送逻辑不变

**决策**: `stream_end` 事件处理逻辑保持不变 — 自动发送队列中的第一条消息。

**理由**: 现有逻辑已经正确，无需修改。

### 4. 新增 `sendQueuedPromptNow` store action

**决策**: 在 useStore 中新增 `sendQueuedPromptNow(index: number)` 方法，封装"取消当前会话 + 发送指定排队提示词"的逻辑。

**理由**: 将取消+发送的复合操作封装为单一 action，避免组件中分散的副作用逻辑。

## Risks / Trade-offs

- [取消后立即发送可能有竞态] → cancelPrompt 调用 ACP `cancel` 后立即发送新 prompt，ACP 协议的 cancel 是异步的，agent 可能还在处理取消。缓解：现有 ESC+自动发送逻辑已有相同问题，且实际使用中 agent 通常能快速响应 cancel。
- [多个排队消息时箭头按钮可能造成混淆] → 用户可能不理解"发送这一条"意味着跳过前面的排队消息。缓解：UI 上箭头图标明确表示"提升优先级"，且发送后其他排队消息仍在队列中。
